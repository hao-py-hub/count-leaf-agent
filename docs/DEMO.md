# 5 分钟演示流程

本流程用于展示“可审计油菜表型视觉 Agent”的业务闭环，不用于宣称图像计数准确率。

## 0. 启动

Windows PowerShell：

```powershell
.\.venv312\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

打开 `http://127.0.0.1:8000/`，先确认顶部服务状态正常；也可访问 `http://127.0.0.1:8000/api/health`。

## 1. 发起分析（约 1 分钟）

1. 点击顶部“研究助手”，将“项目 ID”填写为 `demo-rapeseed`。
2. 点击“分析图片”上传一张完整植株考种照片，按提示确认提交；或选择“批量分析”上传少量图片。
3. 观察助手返回的任务 ID、状态流和 `trace_id`，说明分析由异步任务执行，而不是在对话中直接编造计数。
4. 完成后在左侧历史记录打开结果，展示主干/主枝/分枝明细、角果总数和步骤图。

可强调：VLM 只负责结构定位与复核，计数读取 CV 流水线结果；当前没有可对外宣称的整株图像算法准确率。

## 2. 人工复核与版本链（约 1 分钟）

1. 点击顶部“任务中心”→“复核队列”。
2. 如果质量或冲突规则触发了复核，打开复核详情；也可在已完成任务结果中手动创建复核。
3. 选择“打开结果并人工修订结案”，调整部件数量后保存。
4. 展示原始自动结果仍被保留，而人工修订生成新版本并把复核置为 `resolved`；关闭复核则保留自动结果并记录 `dismissed`。

可强调：写操作必须显式确认，未确认写操作不执行。

## 3. 运营与审计（约 1 分钟）

在“任务中心”中依次展示：

1. “运营指标”：缓存命中、模型调用、token/估算成本、复核数量和未确认写操作率。
2. “审计记录”：Agent 工作流与工具调用的脱敏元数据。
3. “事件对账”：`AnalysisSubmitted`、`AnalysisCompleted`、`ReviewCreated`、`ReviewResolved`、`ReportGenerated` 等领域事件，与审计账本的数量一致性。

可强调：`trace_id` 串联 HTTP、Agent、Worker、模型调用、人工复核和事件投影；账本不保存 API Key、原图路径或完整提示词。

## 4. 项目隔离（约 1 分钟）

1. 将“项目 ID”改为 `demo-empty` 并刷新任务中心。
2. 任务、批次、复核、报告和领域事件均显示为空或仅显示该项目数据。
3. 切回 `demo-rapeseed`，原先数据重新可见。

可强调：当前为单机单用户 MVP，但 `project_id` 已作为数据与审计查询的隔离边界；OIDC/RBAC 和真实多租户部署属于后续生产化范围。

## 5. 企业 Agent 接入（约 1 分钟）

说明系统同时提供 Function Calling 与本地 MCP `stdio`：MCP 仅开放 6 项只读工具（结果、质量、历史统计、复核和知识检索），不开放文件、SQL、Shell、分析提交或结果写入。需要写入时必须回到 REST/UI 的确认流程。

## 演示结束语

“这个项目不是把视觉模型包成聊天框，而是把油菜表型分析拆成受控的异步任务、版本化结果、人工复核、只读 Agent 接入和可对账审计链；研究人员能看结果，运营人员能追踪成本和异常，外部 Agent 只能在授权边界内读取结构化信息。”
